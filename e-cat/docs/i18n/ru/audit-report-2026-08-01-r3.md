## 2. Новые проблемы R3

### 2.1 [Средняя] Привязка параметров в `execute_with` / `query_with` — пустышка

- **Файл**: `ecat-data/src/rdbms.rs:68-86` / `ecat-data-sqlx/src/lib.rs`
- **Проблема**: в trait `RdbmsClient` добавлены `execute_with(sql, params)` и `query_with(sql, params)`, но реализация по умолчанию напрямую отбрасывает параметр `params` и вызывает исходный `execute(sql)`. `SqlxClient` ни разу не переопределяет эти методы. Разработчик, видя методы с `_with`, думает, что есть защита привязкой параметров, а риск «голого» SQL остаётся
- **Исправление**: `SqlxClient` переопределяет `execute_with` / `query_with`, используя настоящую параметризацию через `sqlx::query(sql).bind(...)`

### 2.2 [Низкая] Молчаливый откат в Transaction::Drop без лога

- **Файл**: `ecat-data/src/rdbms.rs:54-59`
- **Проблема**: если Transaction сбрасывается без вызова `commit()`, Drop лишь комментирует auto-rollback без какого-либо вывода tracing. Молчаливый откат незакоммиченной транзакции может привести к потере данных, которую трудно отладить
- **Рекомендация**: добавить в `Drop` вызов `tracing::warn!("transaction rolled back without commit")`

### 2.3 [Низкая] Захардкоженный ключ "global" в RateLimitLayer

- **Файл**: `ecat-middleware/src/ratelimit.rs:99`
- **Проблема**: `call()` неизменно использует `allow("global")` — все запросы делят один bucket скорости, невозможно тонкое ограничение по IP/маршруту/пользователю
- **Рекомендация**: разрешить передачу замыкания извлечения ключа при конструировании

### 2.4 [Низкая] Row::new не проверяет длины columns/values

- **Файл**: `ecat-data/src/rdbms.rs:12-14`
- **Проблема**: принимаются произвольные `columns` и `values` без проверки совпадения длин. `get()` может вернуть не ту колонку
- **Рекомендация**: `debug_assert_eq!(columns.len(), values.len())`

### 2.5 [Информация] У 5 crates по-прежнему ноль тестов

| Crate | Тесты | Риск |

| ecat-data-sqlx | 0 | Транзакции/параметризованные запросы без интеграционной проверки |

## 3. Оценка качества

**После трёх раундов аудита код значительно улучшился**:
- Компиляция/lint/тесты полностью зелёные, ноль предупреждений
- Версии/edition унифицированы через наследование workspace
- Замкнутый контур защиты: SecurityLayer обнаруживает + блокирует, RateLimitLayer ограничивает скорость
- Инфраструктура graceful shutdown серверов на месте
- Transaction-ядро поддерживает реальный дескриптор транзакции БД

**Оставшиеся разрывы**:
- Параметризованным запросам нужна реальная привязка параметров
- Не хватает интеграционных тестов БД/HTTP-сервера
- CLI proto/run/build по-прежнему заглушечно печатают
- Функциональность RateLimitLayer упрощена
