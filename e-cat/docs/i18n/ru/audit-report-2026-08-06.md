## 2. Проблемы времени выполнения (обнаружены смоук-тестом)

### [HIGH] D1. `HttpServer::new(":8000")` не запускается в среде без IPv6
- **Место**: `ecat-transport-http/src/lib.rs:40`, `examples/helloworld/src/main.rs:41`, README во многих местах
- **Симптом**: `TcpListener::bind(":8000")` резолвится в IPv6-wildcard `[::]:8000`; на машинах без IPv6 (контейнеры/часть облачных хостов) возвращается `failed to lookup address information: Name or service not known`, сервис не стартует.
- **Воспроизведение**: отдельная минимальная программа — `bind(":8001")` падает, `bind("0.0.0.0:8002")` работает, `bind("localhost:8003")` работает.
- **Исправление**: `HttpServer::new` внутри нормализует пустой host в `"0.0.0.0"`; примеры и документация единообразно используют `"0.0.0.0:8000"`.

### [LOW] D2. `cargo clippy --all-targets -- -D warnings` не проходит
- **Место**: `ecat-data-sqlx/src/lib.rs` (после тестового модуля есть items, срабатывает `items_after_test_module`)
- **Влияние**: текущая команда clippy в CI (без `--all-targets`) не затронута; при ужесточении CI упадёт.
- **Исправление**: тестовый модуль перенесён в конец файла.

## 3. Критичные проблемы (CRITICAL)

### [CRITICAL] C1. `ecat-data-memcached` — «фейковая реализация»
- **Место**: `ecat-data-memcached/src/lib.rs:23-88`
- **Проблема**: весь crate — чистый in-memory `HashMap`, без сетевого подключения и конфигурации адреса сервера (`MemcachedConfig` содержит только username/password/tls); description в Cargo.toml сам признаёт: "in-memory cache client". Использование в production приведёт к **молчаливой потере данных** (после перезапуска всё пусто, между экземплярами нет общего состояния).
- **Исправление**: подключить реальный протокол memcached (например, crate `memcache`) или явно пометить `#[deprecated]`/документально запретить использование в production.

### [CRITICAL] C2. TDengine: SQL-инъекция через конкатенацию при записи
- **Место**: `ecat-data-tdengine/src/lib.rs:91-116`
- **Проблема**: в `INSERT INTO "{}" ({}) VALUES ({})` measurement/имена колонок/значения склеиваются через `format!`; строковые значения лишь оборачиваются в двойные кавычки без экранирования `"` и `\`. Значение поля вида `"; DELETE ...; --` может выйти из строки и выполнить произвольный SQL (REST TDengine поддерживает многооператорные запросы).
- **Исправление**: экранировать идентификаторы и строковые значения (`"`→`\"`, `\`→`\\`) или перейти на параметризованный интерфейс записи.

## 4. Проблемы высокого риска (HIGH)

### [HIGH] H1. У всех HTTP-адаптеров БД нет таймаутов
- **Место**: `ecat-tls/src/lib.rs:27,61`, elasticsearch/opensearch/clickhouse/influxdb/iotdb/questdb/tdengine/neo4j/nebulagraph/arangodb
- **Проблема**: у reqwest нет таймаута по умолчанию; при зависшем сервере запрос **висит вечно** (истощение пула соединений, утечка задач).
- **Исправление**: в `build_reqwest_client` единообразно задать `connect_timeout` (например, 5s) + `timeout` (например, 30s).

### [HIGH] H2. Лимит скорости невозможно привязать к клиенту
- **Место**: `ecat-middleware/src/ratelimit.rs:155`
- **Проблема**: `key_fn("")` не получает объект запроса — нельзя ограничивать по IP/пользователю; по умолчанию одна бочка "global": атакующий может исчерпать глобальную квоту (DoS для остальных) или обойти через распределённые запросы.
- **Исправление**: изменить сигнатуру `key_fn` на приём `&http::Request`, извлекать ключ из `X-Forwarded-For`/адреса собеседника.

### [HIGH] H3. GitHub CI гарантированно падает (нет protoc)
- **Место**: `.github/workflows/ci.yml`
- **Проблема**: build.rs в `ecat-protos` компилирует proto через tonic-build, жёстко зависящий от protoc; в GH CI не установлен `protobuf-compiler` (локально проходит, потому что есть `/home/erik/.local/bin/protoc`). В `.gitlab-ci.yml` он установлен — поведение двух CI различается.
- **Исправление**: добавить в GH CI `apt-get install protobuf-compiler` (и cmake, если потребуется).

### [HIGH] H4. Elasticsearch: `search()`/`delete()` не проверяют HTTP-код статуса
- **Место**: `ecat-data-elasticsearch/src/lib.rs:87-114`
- **Проблема**: тело ошибки 404/400 разбирается как JSON и выдаёт вводящую в заблуждение ошибку "es parse"; `index()` проверяет, а `search`/`delete` — нет, поведение непоследовательно (в opensearch правильно).
- **Исправление**: единообразно проверять `status.is_success()`.

### [HIGH] H5. IoTDB: подозрение на несовместимость протокола `insertTablet`
- **Место**: `ecat-data-iotdb/src/lib.rs:51-82`
- **Проблема**: REST `insertTablet` IoTDB требует массивы формата `timestamps/measurements/values/data_types`; эта реализация отправляет одиночный JSON-документ — возможно, «выглядит реализованным, а не работает».
- **Исправление**: формировать тело запроса по спецификации insertTablet и добавить интеграционный тест.

### [HIGH] H6. Префикс deregister в etcd не совпадает (deregister не работает)
- **Место**: `ecat-registry-etcd/src/lib.rs:47,66`
- **Проблема**: ключ регистрации — `/ecat/services/{prefix}/{name}/{uuid}`, а deregister удаляет `{prefix}/{name}` (не хватает сегмента uuid) → после выхода экземпляра запись о регистрации остаётся.
- **Исправление**: при удалении сопоставлять полный ключ или удалять по префиксу name после list.
