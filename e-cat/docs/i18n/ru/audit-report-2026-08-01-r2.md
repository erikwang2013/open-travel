## 2. Новые проблемы этого раунда

### 2.1 [Критично] Сгенерированный шаблоном CLI `new` код не компилируется

- **Файл**: `ecat-cli/src/main.rs:79-97`
- **Проблема**: сгенерированный `Cargo.toml` использует ссылки на зависимости `workspace = true` и относительный путь `path = "../ecat"`, но независимый проект, созданный через `ecat new myapp`, не находится внутри workspace e-cat — все эти ссылки не разрешатся
- **Влияние**: проект, созданный через `ecat new`, вообще не компилируется
- **Исправление**: шаблон должен использовать реальные версионированные зависимости, а не workspace-ссылки

```toml
# 当前（错误）：
tokio.workspace = true           # 项目不在 workspace 中，报错
ecat = { path = "../ecat" }      # 相对路径无效

# 应改为：
tokio = { version = "1", features = ["full"] }
ecat = "1.0.5"
```

### 2.2 [Критично] `transaction()` в ecat-data-sqlx отбрасывает реальный дескриптор транзакции БД

- **Файл**: `ecat-data-sqlx/src/lib.rs:100-106`
- **Проблема**: `pool.begin()` возвращает реальный дескриптор транзакции БД `Transaction<'_, DB>`, но код привязывает его как `_tx` и немедленно отбрасывает. При drop `_tx` транзакция БД автоматически откатывается. Возвращаемый `ecat_data::Transaction` — пустышка, его `commit()/rollback()` не дают никакого эффекта
- **Влияние**: весь код, использующий `transaction()`, работает без защиты транзакцией; согласованность данных не гарантируется
- **Исправление**: перепроектировать структуру `ecat_data::Transaction`, чтобы она удерживала реальный дескриптор транзакции БД

### 2.3 [Средняя] SecurityLayer не сканирует тело запроса

- **Файл**: `ecat-security/src/lib.rs:117-127`
- **Проблема**: `call()` сканирует только URI и HTTP-заголовки, тело запроса вообще не проверяется. Атакующий может легко обойти детекцию, поместив SQL-инъекцию/XSS payload в POST body
- **Влияние**: существенно снижает эффективное покрытие обнаружения атак
- **Исправление**: добавить возможность сканирования тела или публичный метод `scan_body()` для вызова после чтения тела

### 2.4 [Средняя] RateLimitLayer использует синхронный Mutex + нет очистки просрочки

- **Файл**: `ecat-middleware/src/ratelimit.rs:10-38`
- **Проблема 1**: `std::sync::Mutex` используется в асинхронном контексте — при конкуренции за блокировку блокируется весь worker-поток tokio
- **Проблема 2**: `buckets: HashMap<String, (u32, Instant)>` никогда не очищает просроченные ключи; у долго работающего сервера память растёт бесконечно (каждый новый IP/ключ навсегда занимает память)
- **Влияние**: падение производительности при высокой конкуренции, утечка памяти при долгой работе
- **Исправление**: перейти на `tokio::sync::Mutex` и периодически очищать просроченные записи в `allow()`

### 2.5 [Средняя] В ecat-data-sqlx нет параметризованного API для «голого» SQL

- **Файл**: `ecat-data-sqlx/src/lib.rs:24-29, 32-36`
- **Проблема**: `execute(&self, sql: &str)` и `query(&self, sql: &str)` принимают только строку SQL; на уровне trait нет методов привязки параметров. Если вызывающий код конкатенирует пользовательский ввод в SQL, возможна SQL-инъекция
- **Влияние**: хотя сам trait напрямую не создаёт уязвимость, отсутствие параметризованного API провоцирует вызывающих писать небезопасный код
- **Рекомендация**: добавить в trait `RdbmsClient` методы `execute_with` и `query_with` с привязкой параметров

### 2.6 [Низкая] Arc::clone в query() по-прежнему внутри замыкания

- **Файл**: `ecat-data-sqlx/src/lib.rs:50-53`
- **Проблема**: `let cols = std::sync::Arc::clone(&columns)` выполняется внутри замыкания `rows.iter().map()`. Хотя Arc::clone лёгкий (только атомарный инкремент счётчика ссылок), его можно вынести за пределы замыкания, избегая одной атомарной операции на строку
- **Рекомендация**: сделать один clone перед `iter()` и захватить его в замыкании

### 2.7 [Низкая] trait impl ProtoCodec не согласован с новым API

- **Файл**: `ecat-encoding/src/proto.rs`
- **Проблема**: `encode/decode` trait `Codec` по-прежнему возвращают только ошибку; новые `encode_message/decode_message` — корректный путь, но имена методов не совпадают с trait-ом. Пользователь может сначала попробовать `codec.encode()` и недоумевать, почему не работает
- **Рекомендация**: пояснить в документации/комментариях: для proto-типов следует использовать `encode_message/decode_message`, а не методы trait Codec
