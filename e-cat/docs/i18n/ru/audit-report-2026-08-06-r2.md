## 5. Новые находки этого раунда (2 пункта)

### [MEDIUM] A. Dockerfile: `CMD ["ecat"]` завершается сразу при старте
- **Симптом**: CLI `ecat` обязателен с подкомандой; без аргументов clap завершается с ошибкой (exit code 2), контейнер немедленно останавливается, HEALTHCHECK не проходит.
- **Причина**: в образе только бинарник CLI, без пользовательского сервиса; `ecat run` — просто обёртка над `cargo run` (без default-member тоже падает).
- **Рекомендация**: ① при сборке дополнительно упаковать бинарник примера сервиса и задать его CMD; ② или задокументировать, что образ предназначен только для dev-контейнера (монтирование исходников + `ecat run`); ③ или добавить CLI подкоманду `serve`. Это проблема семантики развёртывания, без самовольных изменений.

### [LOW] B. `name: ecat-app` в `Chart.yaml` не совпадает с именем артефакта Dockerfile (`ecat`)
- **Симптом**: имя образа `ecat-app` напрямую не связано с бинарником `ecat`; при развёртывании Helm tag образа нужно указывать вручную.
- **Рекомендация**: задокументировать команды сборки/тегирования образа (`docker build -t ecat-app:2.3.1 .`). Низкий риск, не изменено.
