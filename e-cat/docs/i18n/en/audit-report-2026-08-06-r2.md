## 5. New Findings This Round (2 items)

### [MEDIUM] A. Dockerfile `CMD ["ecat"]` exits immediately on start
- **Symptom**: the `ecat` CLI requires a subcommand; run without arguments, clap errors out (exit code 2), the container terminates immediately, and the HEALTHCHECK can never pass.
- **Cause**: the image only ships the CLI binary, not a user service; `ecat run` is just a wrapper around `cargo run` (it fails the same way without a default-member).
- **Suggestion**: ① also package an example service binary at build time and set it as CMD; ② or document that the image is only for dev containers (mount sources + `ecat run`); ③ or add a `serve` subcommand to the CLI. A deployment-semantics issue; not changed unilaterally.

### [LOW] B. `Chart.yaml` `name: ecat-app` inconsistent with the Dockerfile artifact name (`ecat`)
- **Symptom**: the image name `ecat-app` has no direct mapping to the `ecat` binary; the image tag must be specified manually when deploying via Helm.
- **Suggestion**: document the image build/tag command (`docker build -t ecat-app:2.3.1 .`). Low risk; not changed.
