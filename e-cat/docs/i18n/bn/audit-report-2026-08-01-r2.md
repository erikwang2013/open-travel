## 2. এই রাউন্ডে নতুন আবিষ্কৃত সমস্যা

### 2.1 [গুরুতর] CLI `new`-এর জেনারেট করা টেমপ্লেট কোড কম্পাইল হয় না

- **ফাইল**: `ecat-cli/src/main.rs:79-97`
- **সমস্যা**: জেনারেট করা `Cargo.toml` `workspace = true` ডিপেন্ডেন্সি রেফারেন্স এবং `path = "../ecat"` রিলেটিভ পাথ ব্যবহার করে, কিন্তু `ecat new myapp`-এর তৈরি করা স্বাধীন প্রজেক্ট e-cat workspace-এর ভিতরে নয়, এই রেফারেন্সগুলো সব রেজলভ করতে ব্যর্থ হবে
- **প্রভাব**: `ecat new`-এর তৈরি প্রজেক্ট সম্পূর্ণ কম্পাইল করা যায় না
- **মেরামত**: টেমপ্লেটে workspace রেফারেন্সের বদলে ভার্সনসহ প্রকৃত ডিপেন্ডেন্সি ব্যবহার করা উচিত

```toml
# বর্তমান (ভুল):
tokio.workspace = true           # প্রজেক্ট workspace-এ নেই, এরর হবে
ecat = { path = "../ecat" }      # রিলেটিভ পাথ অবৈধ

# বদলে হওয়া উচিত:
tokio = { version = "1", features = ["full"] }
ecat = "1.0.5"
```

### 2.2 [গুরুতর] ecat-data-sqlx `transaction()` প্রকৃত ডেটাবেস ট্রানজেকশন হ্যান্ডেল ফেলে দেয়

- **ফাইল**: `ecat-data-sqlx/src/lib.rs:100-106`
- **সমস্যা**: `pool.begin()` প্রকৃত ডেটাবেস ট্রানজেকশন হ্যান্ডেল `Transaction<'_, DB>` ফেরত দেয়, কিন্তু কোড `_tx` দিয়ে বাঁধার পরই তা ফেলে দেয়। `_tx` drop হলে ডেটাবেস ট্রানজেকশন স্বয়ংক্রিয়ভাবে rollback হয়। ফেরত দেওয়া `ecat_data::Transaction` একটি খালি খোলস, এর `commit()/rollback()` মেথডের কোনো প্রভাব নেই
- **প্রভাব**: `transaction()` ব্যবহার করা সব কোড ট্রানজেকশন সুরক্ষা ছাড়াই চলছে, ডেটা কনসিস্টেন্সি নিশ্চিত করা যায় না
- **মেরামত**: `ecat_data::Transaction` স্ট্রাক্ট পুনর্নির্মাণ করা দরকার, যাতে এটি প্রকৃত ডেটাবেস ট্রানজেকশন হ্যান্ডেল ধারণ করে

### 2.3 [মাঝারি] SecurityLayer রিকোয়েস্ট বডি স্ক্যান করে না

- **ফাইল**: `ecat-security/src/lib.rs:117-127`
- **সমস্যা**: `call()` শুধুমাত্র URI এবং HTTP হেডার স্ক্যান করে, রিকোয়েস্ট বডি একেবারেই পরীক্ষা করে না। আক্রমণকারী POST body-তে SQL injection/XSS payload রাখলে সহজেই সনাক্তকরণ এড়িয়ে যেতে পারে
- **প্রভাব**: আক্রমণ সনাক্তকরণের কার্যকর কভারেজ ব্যাপকভাবে কমে যায়
- **মেরামত**: body স্ক্যান ক্ষমতা যোগ করা দরকার, অথবা `scan_body()` পাবলিক মেথড দেওয়া দরকার যাতে কলকারী body পড়ার পর তা ব্যবহার করতে পারে

### 2.4 [মাঝারি] RateLimitLayer সিঙ্ক্রোনাস Mutex + মেয়াদোত্তীর্ণ ক্লিনআপ নেই

- **ফাইল**: `ecat-middleware/src/ratelimit.rs:10-38`
- **সমস্যা 1**: `std::sync::Mutex` async কনটেক্সটে ব্যবহৃত — লক কনটেনশন হলে পুরো tokio worker থ্রেড ব্লক হয়ে যাবে
- **সমস্যা 2**: `buckets: HashMap<String, (u32, Instant)>` থেকে মেয়াদোত্তীর্ণ key কখনো পরিষ্কার হয় না, দীর্ঘক্ষণ চলমান সার্ভারে মেমরি অসীমভাবে বৃদ্ধি পায় (প্রতিটি নতুন IP/key স্থায়ীভাবে মেমরি দখল করে)
- **প্রভাব**: উচ্চ কনকারেন্সিতে পারফরম্যান্স হ্রাস, দীর্ঘক্ষণ চলার পর মেমরি লিক
- **মেরামত**: `tokio::sync::Mutex` ব্যবহার করা, এবং `allow()`-এ নিয়মিত মেয়াদোত্তীর্ণ এন্ট্রি পরিষ্কার করা

### 2.5 [মাঝারি] ecat-data-sqlx বেয়ার SQL-এ প্যারামিটারাইজড API নেই

- **ফাইল**: `ecat-data-sqlx/src/lib.rs:24-29, 32-36`
- **সমস্যা**: `execute(&self, sql: &str)` এবং `query(&self, sql: &str)` শুধুমাত্র কাঁচা SQL স্ট্রিং গ্রহণ করে, trait স্তরে প্যারামিটার বাইন্ডিং মেথড নেই। কলকারী SQL-এ ইউজার ইনপুট জোড়া দিলে SQL injection হতে পারে
- **প্রভাব**: trait নিজে সরাসরি নিরাপত্তা দুর্বলতা প্রকাশ করে না, কিন্তু প্যারামিটারাইজড API-এর অভাব কলকারীকে অসুরক্ষিত কোড লিখতে প্রলুব্ধ করে
- **পরামর্শ**: `RdbmsClient` trait-এ প্যারামিটার বাইন্ডিংসহ `execute_with` এবং `query_with` মেথড যোগ করা

### 2.6 [কম] query()-এ Arc::clone এখনও ক্লোজারের ভিতরে

- **ফাইল**: `ecat-data-sqlx/src/lib.rs:50-53`
- **সমস্যা**: `let cols = std::sync::Arc::clone(&columns)` `rows.iter().map()` ক্লোজারের ভিতরে executes হয়। Arc::clone খুব হালকা হলেও (শুধু অ্যাটমিক রেফারেন্স কাউন্ট বৃদ্ধি), এটি ক্লোজারের বাইরে নেওয়া যায় প্রতি সারিতে একবার অ্যাটমিক অপারেশন এড়াতে
- **পরামর্শ**: `iter()`-এর আগে একবার clone করুন, ক্লোজারটি সেই clone ধারণ করবে

### 2.7 [কম] ProtoCodec-এর trait impl নতুন API-এর সাথে অসামঞ্জস্যপূর্ণ

- **ফাইল**: `ecat-encoding/src/proto.rs`
- **সমস্যা**: `Codec` trait-এর `encode/decode` এখনও শুধু এরর ফেরত দেয়; নতুন যোগ করা `encode_message/decode_message` সঠিক পথ কিন্তু মেথডের নাম trait-এর সাথে মেলে না। ব্যবহারকারী আগে `codec.encode()` চেষ্টা করে বিভ্রান্ত হতে পারেন কেন ব্যর্থ হচ্ছে
- **পরামর্শ**: ডকুমেন্টেশন/মন্তব্যে ব্যাখ্যা করুন: proto টাইপের জন্য `encode_message/decode_message` ব্যবহার করা উচিত, Codec trait মেথড নয়
