## 2. इस दौर की नई समस्याएँ

### 2.1 [गंभीर] CLI `new` द्वारा जनरेटेड टेम्पलेट कोड कंपाइल नहीं होता

- **फ़ाइल**: `ecat-cli/src/main.rs:79-97`
- **समस्या**: जनरेटेड `Cargo.toml` में `workspace = true` निर्भरता संदर्भ और `path = "../ecat"` सापेक्ष पथ उपयोग होता है, लेकिन `ecat new myapp` द्वारा बनाया गया स्टैंडअलोन प्रोजेक्ट e-cat workspace के बाहर है, ये सभी संदर्भ resolve विफल होंगे
- **प्रभाव**: `ecat new` से बनाया गया प्रोजेक्ट कंपाइल ही नहीं हो सकता
- **मरम्मत**: टेम्पलेट में workspace संदर्भ के बजाय संस्करण सहित वास्तविक निर्भरताएँ उपयोग करें

```toml
# वर्तमान (गलत):
tokio.workspace = true           # प्रोजेक्ट workspace में नहीं है, त्रुटि
ecat = { path = "../ecat" }      # सापेक्ष पथ अमान्य

# इसे बदलकर:
tokio = { version = "1", features = ["full"] }
ecat = "1.0.5"
```

### 2.2 [गंभीर] ecat-data-sqlx `transaction()` वास्तविक डेटाबेस ट्रांज़ैक्शन हैंडल छोड़ देता है

- **फ़ाइल**: `ecat-data-sqlx/src/lib.rs:100-106`
- **समस्या**: `pool.begin()` वास्तविक डेटाबेस ट्रांज़ैक्शन हैंडल `Transaction<'_, DB>` लौटाता है, लेकिन कोड इसे `_tx` से बांधकर तुरंत छोड़ देता है। जब `_tx` drop होता है, डेटाबेस ट्रांज़ैक्शन स्वतः रोलबैक होता है। लौटाया गया `ecat_data::Transaction` खोखला है, इसका `commit()/rollback()` तरीका बेअसर है
- **प्रभाव**: `transaction()` उपयोग करने वाला सभी कोड बिना ट्रांज़ैक्शन सुरक्षा के चलता है, डेटा स्थिरता की गारंटी नहीं
- **मरम्मत**: `ecat_data::Transaction` संरचना को फिर से डिज़ाइन करने की आवश्यकता है, ताकि वह वास्तविक डेटाबेस ट्रांज़ैक्शन हैंडल रखे

### 2.3 [मध्यम] SecurityLayer अनुरोध बॉडी स्कैन नहीं करता

- **फ़ाइल**: `ecat-security/src/lib.rs:117-127`
- **समस्या**: `call()` केवल URI और HTTP हेडर स्कैन करता है, अनुरोध बॉडी की पूरी तरह जाँच नहीं करता। हमलावर SQL इंजेक्शन/XSS payload को POST body में रखकर आसानी से पता लगाने को बायपास कर सकते हैं
- **प्रभाव**: हमले का पता लगाने की प्रभावी कवरेज काफी कम हो जाती है
- **मरम्मत**: बॉडी स्कैन क्षमता जोड़ने की आवश्यकता है, या `scan_body()` सार्वजनिक विधि प्रदान करें जिसे कॉलर बॉडी पढ़ने के बाद उपयोग कर सके

### 2.4 [मध्यम] RateLimitLayer सिंक्रोनस Mutex + कोई समाप्ति सफाई नहीं

- **फ़ाइल**: `ecat-middleware/src/ratelimit.rs:10-38`
- **समस्या 1**: `std::sync::Mutex` async संदर्भ में उपयोग — यदि लॉक प्रतिस्पर्धा होती है, तो पूरा tokio worker थ्रेड ब्लॉक हो जाता है
- **समस्या 2**: `buckets: HashMap<String, (u32, Instant)>` समाप्त कुंजियों को कभी साफ़ नहीं करता, लंबे समय तक चलने वाले सर्वर की मेमोरी असीमित रूप से बढ़ती है (हर नया IP/key स्थायी रूप से मेमोरी घेरता है)
- **प्रभाव**: उच्च समवर्तीता पर प्रदर्शन गिरता है, लंबे समय तक चलने पर मेमोरी लीक
- **मरम्मत**: `tokio::sync::Mutex` में बदलें, और `allow()` में समाप्त प्रविष्टियों को नियमित रूप से साफ़ करें

### 2.5 [मध्यम] ecat-data-sqlx बिना पैरामीटराइज़ेशन API वाला नग्न SQL

- **फ़ाइल**: `ecat-data-sqlx/src/lib.rs:24-29, 32-36`
- **समस्या**: `execute(&self, sql: &str)` और `query(&self, sql: &str)` केवल कच्चे SQL स्ट्रिंग स्वीकार करते हैं, trait स्तर पर कोई पैरामीटर बाइंडिंग विधि नहीं। कॉलर उपयोगकर्ता इनपुट को SQL में जोड़ता है, तो SQL इंजेक्शन होता है
- **प्रभाव**: हालाँकि trait स्वयं सीधे सुरक्षा छेद उजागर नहीं करता, पैरामीटराइज़्ड API की कमी कॉलर को असुरक्षित कोड लिखने के लिए प्रेरित करती है
- **सुझाव**: `RdbmsClient` trait में पैरामीटर बाइंडिंग के लिए `execute_with` और `query_with` विधियाँ जोड़ें

### 2.6 [कम] query() में Arc::clone अभी भी क्लोजर के अंदर

- **फ़ाइल**: `ecat-data-sqlx/src/lib.rs:50-53`
- **समस्या**: `let cols = std::sync::Arc::clone(&columns)` `rows.iter().map()` क्लोजर के अंदर निष्पादित होता है। हालाँकि Arc::clone बहुत हल्का है (केवल परमाणु संदर्भ गणना वृद्धि), इसे क्लोजर के बाहर निकालकर प्रति पंक्ति परमाणु ऑपरेशन से बचा जा सकता है
- **सुझाव**: `iter()` से पहले एक बार clone करें, क्लोजर में उस clone को कैप्चर करें

### 2.7 [कम] ProtoCodec का trait impl नए API के साथ असंगत

- **फ़ाइल**: `ecat-encoding/src/proto.rs`
- **समस्या**: `Codec` trait का `encode/decode` अभी भी केवल त्रुटि लौटाता है; नए `encode_message/decode_message` सही पथ हैं लेकिन विधि नाम trait से मेल नहीं खाते। उपयोगकर्ता पहले `codec.encode()` आज़मा सकता है और फिर उलझन में पड़ सकता है कि यह विफल क्यों हुआ
- **सुझाव**: दस्तावेज़/टिप्पणी में बताएँ: proto प्रकारों के लिए Codec trait विधियों के बजाय `encode_message/decode_message` उपयोग करें
