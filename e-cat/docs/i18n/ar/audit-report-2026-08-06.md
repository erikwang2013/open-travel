## 2. مشكلات وقت التشغيل (اكتشفها اختبار التشغيل)

### [عالي] D1. `HttpServer::new(":8000")` يفشل في البيئات دون IPv6
- **الموقع**: `ecat-transport-http/src/lib.rs:40`، `examples/helloworld/src/main.rs:41`، مواضع متعددة في README
- **الظاهرة**: `TcpListener::bind(":8000")` يُحل إلى wildcard IPv6 `[::]:8000`، وعلى الأجهزة دون IPv6 (الحاويات/بعض خوادم السحابة) يُبلغ عن `failed to lookup address information: Name or service not known`، فلا يبدأ الخدمة.
- **إعادة الإنتاج**: برنامج مصغر مستقل يؤكد — `bind(":8001")` يفشل، `bind("0.0.0.0:8002")` ينجح، `bind("localhost:8003")` ينجح.
- **الإصلاح**: داخل `HttpServer::new` تُوحَّد الحالة الفارغة إلى `"0.0.0.0"`؛ وتوحيد الأمثلة والوثائق على `"0.0.0.0:8000"`.

### [منخفض] D2. فشل `cargo clippy --all-targets -- -D warnings`
- **الموقع**: `ecat-data-sqlx/src/lib.rs` (توجد عناصر بعد وحدة الاختبارات، ما يثير `items_after_test_module`)
- **التأثير**: أمر clippy الحالي في CI (دون `--all-targets`) غير متأثر؛ إذا شدَّد CI يفشل.
- **الإصلاح**: نقل وحدة الاختبارات إلى نهاية الملف.

## 3. المشكلات الحرجة (CRITICAL)

### [حرج] C1. `ecat-data-memcached` «تنفيذ وهمي»
- **الموقع**: `ecat-data-memcached/src/lib.rs:23-88`
- **المشكلة**: الـ crate بأكمله `HashMap` في الذاكرة فقط، دون اتصال شبكة ودون إعداد عنوان خادم (`MemcachedConfig` يضم username/password/tls فقط)، ويصف description في Cargo.toml نفسه بأنه «in-memory cache client». الاستخدام الخاطئ في الإنتاج يؤدي إلى **فقدان بيانات صامت** (يُمسح عند إعادة التشغيل، ولا مشاركة بين النسخ المتعددة).
- **الإصلاح**: ربط بروتوكول memcached الحقيقي (مثل crate `memcache`)، أو وسمه صراحةً بـ `#[deprecated]`/تحذير في الوثائق يمنع استخدامه في الإنتاج.

### [حرج] C2. حقن عبر تجميع SQL في كتابة TDengine
- **الموقع**: `ecat-data-tdengine/src/lib.rs:91-116`
- **المشكلة**: في `INSERT INTO "{}" ({}) VALUES ({})` يُجمَّع كل من measurement/أسماء الأعمدة/القيم مباشرة عبر `format!`، وقيم السلاسل ملفوفة بعلامتي اقتباس فقط دون تهريب `"` و`\`. يمكن لقيمة حقل تحتوي `"; DELETE ...; --` الهروب لتنفيذ أي SQL (REST الخاص بـ TDengine يدعم عبارات متعددة).
- **الإصلاح**: تهريب المعرّفات وقيم السلاسل (`"`→`\"`، `\`→`\\`)، أو استخدام واجهة كتابة بربط المعاملات.

## 4. المشكلات عالية الخطورة (HIGH)

### [عالي] H1. جميع محولات قواعد البيانات HTTP بلا مهلة
- **الموقع**: `ecat-tls/src/lib.rs:27,61`، elasticsearch/opensearch/clickhouse/influxdb/iotdb/questdb/tdengine/neo4j/nebulagraph/arangodb
- **المشكلة**: reqwest بلا مهلة افتراضية، فعند تعليق الخادم تعلق الطلبات **إلى الأبد** (نضوب تجمع الاتصالات، تسريب المهام).
- **الإصلاح**: `build_reqwest_client` يضبط `connect_timeout` (مثل 5 ثوانٍ) + `timeout` (مثل 30 ثانية) بشكل موحد.

### [عالي] H2. تحديد المعدل لا يعمل حسب العميل
- **الموقع**: `ecat-middleware/src/ratelimit.rs:155`
- **المشكلة**: `key_fn("")` لا يحصل على كائن الطلب، فلا يمكن تحديد المعدل حسب IP/المستخدم؛ السلوك الافتراضي سلة واحدة «global»، فيمكن للمهاجم استنزاف الحصة العامة (DoS للآخرين) أو تجاوزها عبر التوزيع.
- **الإصلاح**: تغيير توقيع `key_fn` لاستقبال `&http::Request`، وأخذ المفتاح من `X-Forwarded-For`/عنوان الطرف المقابل.

### [عالي] H3. فشل GitHub CI حتميًا (نقص protoc)
- **الموقع**: `.github/workflows/ci.yml`
- **المشكلة**: build.rs الخاص بـ `ecat-protos` يترجم proto عبر tonic-build ويتطلب protoc إلزاميًا؛ CI الخاص بـ GH لا يثبّت `protobuf-compiler` (الجهاز المحلي يملك `/home/erik/.local/bin/protoc` لذلك ينجح محليًا). `.gitlab-ci.yml` يثبّته، فسلوك السلوستين CI غير متسق.
- **الإصلاح**: إضافة `apt-get install protobuf-compiler` في CI الخاص بـ GH (وcmake عند الحاجة).

### [عالي] H4. `search()`/`delete()` في Elasticsearch لا يفحص كود حالة HTTP
- **الموقع**: `ecat-data-elasticsearch/src/lib.rs:87-114`
- **المشكلة**: تُحلَّل أجسام أخطاء 404/400 كـ JSON فيُبلَّغ عن خطأ «es parse» مضلل؛ `index()` يفحص الحالة بينما `search`/`delete` لا يفحصانها، سلوك غير متسق (opensearch صحيح).
- **الإصلاح**: فحص `status.is_success()` بشكل موحد.

### [عالي] H5. اشتباه عدم توافق بروتوكول `insertTablet` في IoTDB
- **الموقع**: `ecat-data-iotdb/src/lib.rs:51-82`
- **المشكلة**: يتطلب `insertTablet` في REST الخاص بـ IoTDB مصفوفات `timestamps/measurements/values/data_types`؛ هذا التنفيذ يرسل JSON بمستند واحد، وقد يكون «يبدو منفذًا لكنه غير قابل للاستخدام فعليًا».
- **الإصلاح**: بناء جسم الطلب وفق مواصفات insertTablet، وإضافة اختبارات تكامل.

### [عالي] H6. بادئة deregister في etcd غير متطابقة (deregister بلا تأثير)
- **الموقع**: `ecat-registry-etcd/src/lib.rs:47,66`
- **المشكلة**: مفتاح التسجيل هو `/ecat/services/{prefix}/{name}/{uuid}`، بينما يحذف deregister `{prefix}/{name}` (تنقصه شريحة uuid) → تبقى معلومات التسجيل بعد خروج المثيل.
- **الإصلاح**: مطابقة المفتاح الكامل عند الحذف أو سرد المفاتيح ثم الحذف حسب بادئة الاسم.
